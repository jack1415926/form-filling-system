# 两周可演示 MVP 确认范围

确认日期：2026-09-30。以现有技术方案 1.4 为底稿，数据库按本次确认改用 MySQL，其他技术选型、八张工作表的填报内容和既有规则保留。本说明补充审批与留言流程，并替代原方案中与本次范围冲突的数据库选型、功能排除、后续扩展和实施安排。原 Word、ER 图、序列图及版式保留；现有图展示基础填报部分，新增流程由补充文字说明。原 Word 和序列图中的 PostgreSQL 为历史选型，实际开发以本说明中的 MySQL 选型为准。

## 方案目标与流程

基础链路扩展为：**新建 → 填写与保存 → 指定审批人并提交 → 查看待审批任务 → 留言反馈 → 全部批准**。

申请仅采用三个状态：**草稿 → 待审批 → 已批准**。不设置独立的“填写完成”状态或“发布”操作。

草稿支持填写、修改、保存和重新打开。填写完成后，申请者指定多名审批人并提交申请。提交前保存表单，执行既有必填校验，并校验至少指定一名审批人。提交成功后锁定表单和审批人名单，所有指定人员同时获得各自的待审批任务；此处任务通过待审批列表展示，不增加消息通知。

审批人只能批准分配给自己的任务。个人批准后，该任务从其待审批列表移除，申请继续等待其他人员批准。全部指定人员批准后，申请进入已批准。

待审批期间，申请者和指定审批人可以互相追加留言；个人已经批准的指定审批人，在申请仍处于待审批时可以继续留言。最后一人批准后结束留言，表单、审批结果和留言均只读。

## 最小实现边界

- 沿用现有登录功能，从已有用户中选择审批人员，不增加账号管理或复杂角色配置。
- 提交前保存表单并执行既有必填校验，至少指定一名审批人；提交后不能修改表单或审批人名单。
- 审批人只能批准分配给自己的任务；个人批准后，该任务从其待审批列表移除，申请仍等待其他人员批准。
- 留言按时间顺序展示，双方通过追加留言沟通，不增加留言编辑、删除或嵌套讨论功能。
- 锁定由后端统一执行，覆盖所有表单保存接口；重复批准不产生重复记录，同时批准时正确判断是否全部完成。
- 不增加退回、拒绝、撤回、重新提交、消息通知、Excel 导出或其他功能。

保存每名审批人的批准结果及时间属于本次功能所需数据，不再排除基本审批及审批记录。完整操作日志、字段修改历史、历史版本、并发版本控制、通用动态表单、模板版本管理、扩展字段机制、复杂角色权限、手机端专项适配、历史 Excel 导入和正式模板导出继续排除。

## 数据存储与 ER 补充

数据库采用 MySQL Community Server 8.4 LTS，表使用 InnoDB，字符集使用 `utf8mb4`。后端继续采用 Django 和 Django REST Framework，通过 Django 内置 MySQL 后端及 `mysqlclient` 驱动访问数据库；其他前后端技术选型不变。

2026-09-30 阶段收尾确认：草稿保存时，非空 ECR 编号和非空 ECO 编号分别必须唯一，空编号允许重复。当前阶段代码尚未实现这条唯一性规则，列为阶段一待完成项；确认规则不代表相关校验和数据库约束已经落地。

沿用 `change_request` 及现有物料、处置、问题回答、行动、执行计划和实质性变更评估数据结构。固定问题、行动定义及判断规则仍作为系统配置统一维护，不随每项申请重复保存。

主记录保存申请者和申请状态。增加审批记录，保存申请与审批人的关联、批准结果和批准时间；增加留言记录，保存所属申请、留言人、内容和时间。

一项申请与审批记录为一对多关系，每名指定审批人对应一项任务；一项申请与留言记录为一对多关系。具体表名和字段定义在第 1—2 天确认。数据库约束和事务处理需保证同一申请与审批人组合不出现重复记录，并在同时批准时正确判断是否全部完成。

提交、批准和留言写入需在数据库事务内校验申请状态；涉及状态转换时锁定对应申请主记录，使表单保存、提交锁定、最后一人批准和结束留言正确衔接。审批记录设置申请与审批人的组合唯一约束。验收时使用实际 MySQL 数据库验证并行批准、重复批准及提交后的保存锁定。

现有 ER 图不包含新增审批记录和留言记录，也不代表本次完整实现范围。图内模板版本等属性不改变本次排除版本管理的边界。

## 验收要求

使用一名申请者和至少两名审批人完成以下验证：

1. 申请者新建草稿，填写八张工作表并保存；重新打开后恢复已填内容，既有规则正确执行。
2. 提交时完成保存和既有必填校验，至少选择一名审批人；本次端到端验收选择至少两名审批人。
3. 提交后申请状态为待审批，申请者无法修改表单或审批人名单；后端拒绝所有相关保存接口的修改请求。
4. 两名审批人均能看到自己的待审批任务；不能批准未分配给自己的任务。
5. 第一名审批人批准后，自己的任务从待审批列表移除，申请仍待审批；申请者和指定审批人可以追加留言，留言按时间顺序展示。
6. 最后一名审批人批准后，申请变为已批准，表单、审批结果和留言全部只读。
7. 重新登录、打开申请后，数据、状态、每名审批人的批准结果及时间、留言均正确恢复。
8. 重复批准不产生重复记录；两名审批人同时批准时，申请最终正确进入已批准。
