# 网页生成测试用例

日期：2026-10-16。

## 需求与实现

脚本需要打开终端并记忆状态参数，人工测试不方便。在工程变更列表增加“生成测试用例”窗口，默认ECR／待批准／当前账号兼任；也可选择ECO、五种目标状态及分别指定行动审核人、批准人、发布人。申请人固定为当前登录用户，成功后显示编号、ID和来源，可直接打开申请继续测试。

复用现有脚本的样例和完整流转方法，未新增业务状态或迁移。接口仅在DEBUG环境提供、需要有效登录和当前账号校验，严格限制输入；只创建合成测试申请，不修改已有数据或密码。同一生成请求按UUID生成唯一编号，锁定申请人串行处理重复请求；相同内容返回原申请，变更内容或账号返回409。整批失败回滚。

## 追加：行动负责人及批准人多选

## 追加：题目、物料及行动一致性修复

现象：默认样例填入升版物料但问题6为否，27题全部否仍有问题1的行动；其他未触发行动也有人员和结果。原因是生成器固定全部回答N，给所有行动预填数据，再用extra_required强行纳入首项；旧专项只验证目标状态及证据，没有校验样例业务内容的一致性。新增最小回归先复现问题6的N/Y失败，再修复共用生成方法，脚本和网页同时生效。

新版固定为自制、非关键、非可追溯、非维修备件连接件的内部受控描述A→B升版，实物、规格、用途及工艺不变，不涉及外购件。问题6为Y、其余N并解释场景；按当前定义分别创建ECR／ECO中问题6对应的11项行动，不勾额外必做，不向其他行动写入人员或结果。各项评估／执行结果与场景匹配，不适用项给出原因；单人11项任务，多人按行动×人数生成并逐人确认、批准。

一并移除问题7为N时的EMC虚构备注、无关的全11项执行计划和未触发的实质性评估子题；保留EMC空参考模板、物料验证与发布计划，人工评估沿0否→A否→B否到合成场景的非实质性结论，其他Chart及子题留空。未修改正式业务的手工补充能力、题目映射、权限或状态；无新增迁移。ECO中的来源ECR仍按来源已发布内容只读显示。

验证：六项真实MySQL专项通过，覆盖两类流程各五种状态、单人及多人、材料升版／问题6／11项行动／任务／轮次快照对应、全部N时本单无行动数据及无必做任务，以及原权限、回滚和重试检查。前端TypeScript／Vite原生配置构建与lint通过；未执行全量回归。独立测试库真实网页生成ECR待批准，确认问题6为是、其余否；行动页只显示ecr_009至ecr_019且均为问题6，已确认11/11、批准0/1。页面证据保存在本机`.local/test-case-generator/consistent-actions.png`。
