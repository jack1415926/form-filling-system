## 保存与身份

| 曾出现的问题 | 当前防护与测试 |
| --- | --- |
| 保存回包覆盖请求期间的新输入、清空后反复发送空值 | Autosave按字段维护基线和在途修改；自动与手动保存串行。保留autosave、material-save、execution-plan及significant-change专项 |
| 子表保存把旧概述拼成“新版本”，迟到GET无法纠正 | 子表保存后重新读取完整详情；latest-response保留微秒顺序，旧响应不能覆盖新缓存 |
| 保存成功但响应丢失，重试重复新增或擦除后续输入 | 新物料UUID、任务版本及操作回执；先核对原请求，再保存后续修改；ecr-recovery及后端重放／并发回归保留 |
| 请求或JSON正文长时间挂起，页面一直忙碌 | API的30秒总期限包含CSRF、请求与响应正文；api专项验证超时、迟到回调和锁释放 |
| 多窗口换账号后仍发送旧操作 | Session、CSRF和X-Expected-User共同校验，身份变化清理旧缓存；真实登录／单会话回归保留 |
| 普通业务403被误判为登录失效 | 后端为未认证和CSRF分别返回not_authenticated、csrf_failed；普通403保留业务错误且不触发重新登录。DRF会将Session认证缺失返回为403，不能只按HTTP状态判断 |
| 重新登录成功后，旧请求迟到又显示失效提示 | API请求绑定登录状态版本，成功登录／退出后更新版本；旧版本回包不再触发身份、权限或恢复事件，认证拒绝提示重新核对请求 |
| 非JSON的5xx或断网被误导为重新登录 | 按错误码区分校验、权限、缺失、冲突、限流及服务异常；写入断网／超时／5xx为结果未确认，不自动退出，不假定未写入 |
| 问题保存后返回行动页仍显示旧触发条件 | queryRefresh按账号／申请失效stage-workflow；问题专项验证离页后在30秒缓存有效期内重入及账号／申请隔离 |

输入保护不是本地持久备份；基础表同字段仍为后保存者生效，不宣称具备通用多人冲突控制。网络超时表示结果未确认，不等于没有写入。

手动测试重新登录恢复：在同一浏览器的标签页A打开自己的测试草稿概述并保存；标签页B打开完全相同的前端地址后退出登录；A保持不刷新，输入测试文字并等待自动保存。应出现恢复提示且保留输入。用原账号重新登录，确认文字不变、自动保存恢复，显示已保存后再刷新验证持久化。可先输错一次密码，确认输入仍在。不要用刷新A、退出A或换账号来验证内存输入恢复。此操作使同一浏览器共享会话的其他标签页一并退出；无需删除数据库会话或修改账号权限。

恢复入口仅用于认证／CSRF拒绝；普通400／403／404／409／429保留相应提示，5xx／断网保留输入并提醒核对结果。仅明确退出成功会清理当前工作台；账号实际改变时按账号隔离缓存。重新登录不授予已撤销权限，审核／发布结果未知时仍需查询原请求结果，不自动重放这些业务动作。

## 异常响应与结果恢复

2026-10-20核对实际业务错误路径：默认HTTP提示与后端detail／字段明细分开验证；只有401、认证403、CSRF失败触发身份恢复，普通权限拒绝不误报掉线。请求及响应正文共用30秒期限，5xx、网络及不可读200保存响应继续按结果未确认处理；自动保存只有限重试，提交、确认、批准、发布等业务动作不自动重放。

概述／详情复用checkedChange；物料列表、27题、EMC及11条计划在GET／PATCH使用前校验完整结构，避免读取在渲染时崩溃、保存把残缺200当作成功。EMC允许后端合法的稀疏交叉格，不要求所有格都已保存；空物料列表是正常结果。response-safety覆盖拒绝响应后旧缓存与脏输入仍保留。

“查询结果”只读取，不替代重试，也不因清除故障而补发原操作。查无提交／确认／审核凭据时明确显示“已查询”，仍保留原UUID；交接查无回执同样保持结果未知。ECO创建不改变来源ECR时间戳，迟到的无关联响应不得擦除已知关联的创建回执和填写人；若另一操作已创建ECO或发布权限／轮次改变，则结束不能继续的重试，说明须核对当前记录，不把它冒认为原请求成功。

## 阶段、历史与来源

| 曾出现的问题 | 必须保留的回归 |
| --- | --- |
| 个人完成被当成整阶段批准 | 多人任务逐人确认，所有指定批准人同意；ECO实施阶段完成只能保存、不能确认 |
| 改派后沿用另一人的结果，旧轮确认影响新轮 | 重提按行动与负责人继承本人结果，仅作待复核初值；新轮重新确认任务与批准 |
| 原提出者被改派后无法复核，或获得他人任务权限 | 未解决意见的原提出者保留本人复核职责；不因此获得其他任务写权限 |
| 未知提交被另一窗口推进后无法离开 | 优先查原UUID回执，再核对当前轮次与终态，释放已不能执行的重试；未发送输入保留 |
| 退回后仍展示修订正文 | can_read_body与历史权限分开；退回同步body_access，允许保留本地输入，不重新开放实时正文 |
| 旧轮用新正文充当历史，或新轮参与者读取旧轮全文 | 0026起冻结八表内容和定义；独立can_read_snapshot，仅目标轮次参与关系不被新轮指派替代；旧轮空快照明确提示缺失 |
| 复用历史编辑器时读到实时数据或StrictMode重放清空缓存 | 每份历史独立QueryClient、禁止自动查询实时正文，任务不可编辑；轮次、账号和八表导航回归保留 |
| ECO来源编号、标题或多人结果混用 | ECO自身标题／编号独立；来源编号只读，逐人结果及确认凭证保留；published results并入publication专项 |
| 重复创建或交接重试覆盖已修改ECO | 创建唯一关联，核验原请求与目标填写人；交接保留内容、任务、意见及回执，旧填写人不能继续写 |

正式发布不可重开。2026-10-20修复待发布入口：消息使用publication上下文，不再因发布人是否为发起人而进入不同视图；“待我发布／已发布”打开与工程变更相同的当前流程总览。再次从消息打开同一流程时回到总览并刷新发布权限，切换仍受未保存／未知结果保护。发布按钮继续依据publication接口的can_publish，已发布隐藏；审核记录和历史快照保持只读。后端test_review_inbox覆盖ECR／ECO及发布人与发起人相同／不同的消息、列表、正文读取和发布拒绝／终态，历史快照由test_round_snapshots覆盖；界面验证范围见[测试说明](README.md)。

## 删除、消息与数据库

- 整项删除以ECR发起人为授权主体，当前状态不限制明确确认后的删除；关联ECO必须明确一并确认。事务先删ECO、再删ECR，失败整体回滚，其他工程、账号及独立系统反馈保留。
- 草稿不传confirm_delete的兼容路径仍在代码中；非草稿缺少确认返回409。物料专项保留真实CSRF、归属及等待父锁后的重检，名称已明确“未确认删除”。重复的草稿级联／编号释放由engineering_deletion专项覆盖。
- 审核、ECO交接、系统反馈三套已读含义不同。旧快照已读不能清除新消息，本人发送不算新入站，标已读不执行业务；保留版本与并发测试。
- 0027已删除旧普通留言review_feedback；正式意见review_issue和独立系统反馈职责不同。保留旧入口拒绝和legacy记录隔离测试，不保留旧整单提交模拟。
- 行动分配与逐轮任务、当前批准人集合与轮次参与记录、任务与操作回执、意见与事件、实时正文与提交快照各自承担不同职责。不能为减少表数合并历史证据。
- owner文字、owner_user与owners仍有兼容／双写路径；删除字段需单独评估账号PROTECT及旧数据，不因本机为空直接移除。EMC参考副本与交叉格、未填写的实质性子题仍在使用。
- 保留全部历史迁移、非空数据前进／回退、逆迁移守卫、数据库约束及真实并发测试。空测试表和迁移夹具不等于可删功能。

## 职责整理与样本核对

2026-10-16将通用StrictValues／canonical／conflict移至request_values；行动组装、任务数据和重复保存移至stage_actions。阶段／字段／权限检查及父锁继续由调用入口负责，未重构App协调、历史编辑器或取消读取锁。

整理前后，本机18份流程响应与9份快照重算SHA-256摘要相同；9份样本重算的SELECT合计488→350。仅执行只读探针，未改业务数据或已存快照；该数量不是通用耗时基准。当前快照仍为version=1。
