## 接口和数据库核对

前端类型与表单覆盖 serializer 的 11 个可写概述字段；`id/applicant/status/created_at/updated_at` 是 5 个系统只读字段。新建允许空对象并由服务器设置申请者和草稿状态；PATCH 接收字段子集并返回完整记录；日期使用 ISO 日期，清空为 `null`。登录请求和 `user/csrfToken` 返回字段、当前用户及退出返回字段也已对照。

实际 MySQL 的 16 列名称、类型、长度和可空性与 Model 一致；主键为自增 ID；`applicant_id` 指向 `auth_user.id`，Model 为 `PROTECT`，数据库删除规则为 `NO ACTION`；状态 CHECK、InnoDB 和 utf8mb4 均存在。单有效会话复用 Django 现有数据库会话，没有新增表或 migration。

该基线没有 ECR/ECO UNIQUE 约束及保存唯一性校验。这是明确的业务实现缺口，不能写成“完全符合设计”；其唯一性规则见 [MVP](../MVP.md#数据存储与-er-补充)，行动项只维护在 README。

## 发现及修复经过

| 问题 | 修复与验证 |
| --- | --- |
| 登录成功但页面仍停留在登录页 | 避免清空当前用户查询；只移除业务缓存并更新用户，登录／退出／重登验证通过 |
| 退出失败后未保存提醒被提前清除 | 仅在真正离开或退出成功后清除，失败后输入及再次离开提醒保留 |
| 新建和退出请求互相干扰（P2） | 新建／保存期间禁用退出；退出期间禁用新建、打开、输入、保存和返回；阻断请求复现并回归 |
| 测试库同名保护未考虑大小写（P1） | 库名 `casefold()` 后比较；实际 MySQL `lower_case_table_names=1`，无连接的配置测试验证拒绝 |
| 前端整表提交可能覆盖另一页面未修改字段 | 跟踪编辑字段，只提交相应 PATCH；真实页面验证不同字段同时保留 |
| HTTP 2xx 非 JSON 响应可能被误认成功 | 拒绝无效响应并保留输入；模拟 200 HTML，恢复响应后重试成功 |
| 同浏览器另一窗口重登后持续 CSRF 失败 | 写请求读取当前 Cookie，无法读取时取令牌；保留 CSRF 防护，共享上下文实测轮换后保存／退出通过 |
| 保存错误在页面顶部不易发现 | 持久错误移到保存按钮附近，并保留可见失败提示 |
| 用户要求单账号单有效登录会话 | 用登录信号及用户行锁轮换新会话、删除该用户旧会话，覆盖应用与内置登录；旧端无法写入且输入保留 |

原人工反馈保存在本机 `manual/实际人工测试.md` 及截图，不在本文重复原文。“没有删除草稿”和“只有概述页”对应本阶段范围，不据此扩展功能。账号登录策略是用户另行确认的本阶段规则，不是审批阶段开发。

单会话以服务器会话为单位，不按窗口数限制，也不主动关闭浏览器；下一次请求才能确认旧端失效。该实现依赖数据库会话，登录时处理有效会话的成本随数量增长。没有为当前内网 MVP 新增索引表、缓存服务或账号管理页面。

值得保留的实现与工具经验：

- 先核对实际环境和数据库连接，用真实 Excel 实例持续试填；字段按源表合并区域左上角核对，原文件只读且不运行宏。
- 密码迁入不提交的本地配置，依赖固定版本；提交前检查已知秘密和不应提交的资料。
- TypeScript `erasableSyntaxOnly` 要求构造器成员显式赋值。
- Windows 启动脚本只对当前进程采用执行策略参数，并用字符串数组传递单参数。
- 浏览器断言需等待 React 更新及“已保存”状态；切换当前操作窗口，避免后台渲染等待误判。Ant Design 两个汉字按钮的自动间距需在定位时处理。
- 核对并复用已有前端服务；浏览器工具初始化失败后使用已有 Playwright 和本机 Edge，没有修改产品依赖。

本记录是本会话过程整理，不是全部历史命令输出的完整归档，也不是产品操作日志、字段修改历史或版本管理。

## 人工复验流程

在 `http://localhost:5173` 使用本机演示账号，按以下流程反馈结果：

1. 错误密码被拒绝；正确登录进入“我的申请”。
2. 用实际 Excel 填写概述，部分字段留空也能保存；返回列表、重开、刷新、退出重登后数据一致。
3. 单独修改字段及清空日期，确认其余内容保留。
4. 不保存就返回／退出：取消保留输入，确认放弃后重开显示原数据。
5. 同浏览器两窗口共享登录，另一窗口重登后原窗口保存／退出不持续报 CSRF 错误；修改不同字段结果均保留。
6. 独立浏览器或隐私窗口重登同账号，旧端后续读取／保存被拒绝，未保存输入保留。
7. 新建／保存／退出期间的控件保护和失败后的恢复正常；错误在保存按钮附近可见。
8. 第二个账号无法看到第一个账号的草稿；核对字段名称和日期展示符合业务习惯。
9. 编号唯一性待规则实现后再验收，不能把当前重复编号仍可保存判为合格。

人工验证已经开展并产生反馈，当前需要的是修复后复验，不是从未开始的首次验收。是否完成及行动顺序只更新在 README。
