## 修改

- 概述、物料和问题页的刷新／关闭保护统一移到 ChangeEditor，按 dirty 或 busy 阻止卸载；移除原两处重复监听及物料表单因此不再使用的局部 dirty 状态。干净页面不阻止卸载，页内放弃确认仍沿用现有行为。
- 问题保存遇到网络失败、5xx、无法读取的成功响应或未知异常时，保留本次涉及的题和字段为结果未确认；即使输入恢复旧基线，仍允许重试且保留离开保护。重试提交当前值，包含显式清空，不重放旧输入或覆盖未涉及的字段。
- 只有成功响应确认后才清除未确认字段、更新基线并显示已保存。后台读取不能覆盖未确认草稿。明确的 400／401／403／404／405／409 拒绝不新增结果未确认状态，已有未确认字段也不会因此被清除。

2. 问题页修改备注后，beforeunload 被阻止。
3. 模拟 PATCH 提交后丢失响应，服务器模拟值已改变；用户把备注清空后仍显示“上次保存结果未确认，请重试”，保存可用，beforeunload 被阻止，上一页显示放弃确认。
4. 取消离开并重试，实际请求为 `{"responses":{"1":{"remark":""}}}`；服务器模拟值清空，状态变为已保存，保存按钮禁用，beforeunload 不再被阻止。
5. 模拟明确 400 拒绝时，显示普通未保存状态；改回基线后正常显示已保存且禁用保存，不虚报结果未知。
6. 暂缓保存响应期间，显示正在保存，输入及页签禁用，beforeunload 被阻止；响应成功后恢复。
7. 物料抽屉输入后，共有 beforeunload 保护仍生效。

这里检查的是事件处理与组件状态，不冒充操作系统强制退出保护；浏览器是否显示原生离开弹窗受其策略约束。真实 MySQL 61 项结果为本轮审查时通过；本次仅前端修复，未再次运行后端测试。
