# 五种场景测试数据与普通用户内网启动

日期：2026-10-16。

## 需求与实现

人工测试需要跳过逐页填表和逐人操作，直接得到填好的 ECR／ECO 草稿、审核中、待批准、已批准、已发布。新增 `scripts/test-data.ps1` 交互／参数入口及 `seed_workflow` 后端命令，仅新增合成测试申请，使用现有账号，不修改已有申请和账号密码。审核中及待批准均沿用数据库 `pending`，通过任务确认进度区分；不增加状态或迁移。创建 ECO 时先完整发布新的来源 ECR，随后走正式复制接口。提交、确认、批准、发布走业务接口，保存轮次快照和操作证据；整批事务失败回滚。

无 Windows 管理员权限时，新增 `scripts/start-lan.ps1`，复用本机已有普通用户 MySQL 启动器，识别当前 IPv4，向新进程传递主机／CSRF 配置，前端监听 `0.0.0.0:5173`，后端和数据库仍只供本机连接。没有本机 MySQL 启动器的设备提示用户先启动数据库。前端代理增加进程 BACKEND_PORT 优先级，避免与后端端口不同。健康服务校验后复用，不结束未知进程，不修改防火墙。

## 问题与修复

- 实际参数试跑发现 PowerShell 数组中的字符串拼接把人员参数和登录名合在一起，后端拒绝识别。改用字符串插值分别传参；四个账号的实际生成成功。
- Python 在当前 Windows 终端使用本地编码，中文输出出现乱码；测试数据入口固定 Python 标准输出为 UTF-8。
- 受限执行环境无法创建已有 MySQL 启动器所需的临时盘符映射；在该限制外运行原启动器成功，仍为普通用户进程，未申请 Windows 管理员权限。
