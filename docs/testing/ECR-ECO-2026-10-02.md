### 日期部分输入与明确清空

原问题：在已有日期中只删除年份，原生控件 value 为空且 badInput=true，但 ECR／ECO 将空值保存为 null。现保留原填写值、显示不完整提示、禁用保存；概述的手动保存及“保存并切换”也不能绕过。共享控件允许通过清除按钮明确清空，补全后恢复保存。

定位到两个事件细节：Ant Design 克隆的 change 目标会丢失原生日期的 badInput，因此读取原生事件目标；从空日期开始键入年份时 ISO 值仍为空，浏览器可能不发 input/change，因此同时在键盘和失焦时检查。原生部分内容保持可继续填写，不强行重置为原日期。

专属浏览器、真实 React 组件与纯内存接口回归：

- ECO、ECR 已填日期只删除年份：badInput=true、提示出现、保存禁用，模拟服务端原日期保持。
- 概述只删除年份：保存禁用；“保存并切换”停留概述和确认框，概述 PATCH 为0。
- 补全年份后恢复保存；点击明确清除按钮后实际负载为 date:null／planned_eco_date:null。
- ECO 日期原本为空且其他字段已修改：只填年份时禁止保存、PATCH为0；全键盘补成年／月／日后得到2026-02-04，PATCH只含该日期和实际修改的result。
- 演示从空日期只填年份：提示、保存禁用及beforeunload保护生效；完整清空后提示和离开保护解除。
- 正常日期、9999上界、五位年份恢复原值及清空保持正常。

### 保存与读取响应交错

原问题：GET有时间保护，但保存回调无条件写入缓存；旧PATCH响应晚于新GET时列表退回旧负责人。现两页GET与保存回调共用 newestResponse，申请详情时间也按新旧比较保留。比较先统一时区，再保留毫秒以下精度。

ECO和ECR分别通过真实重连事件触发读取、受控暂缓PATCH响应验证：读取已显示负责人B后再释放旧保存响应，列表仍显示B，与模拟服务端一致。进入概述显示最近保存20:02:00，没有回退到旧响应20:01:00。业务请求全部由内存接口截获，未登录真实账号、未写开发库，结束后专属会话关闭。
