## 存储及接口

`0005_materialdisposition` 只创建 `material_disposition`，物料外键 CASCADE、物料／位置组合唯一、处置选项及位置分组 CHECK 均落地。迁移本机前后申请和物料各字段一致，处置初始为空，不预填 NA。分组由后端按十个固定位置键确定，客户端不能指定分组或所属物料。

现有物料 GET／POST／PATCH 返回增加 `dispositions` 字典，每个位置包含处置方式及备注；POST 和 PATCH 接受该结构，新增物料类别拒绝处置字段。PATCH 仅更新提交的格，其余字段保留；两个格均为空删除该位置行。读取列表预取关联处置，避免逐物料读取。父申请行锁和外层事务覆盖基础物料及处置写入，删除物料或申请级联删除处置。UUID 重试也核对处置内容，不同内容返回 409。

## 正式页面回归

使用独立临时账号及已有 agent-browser：

1. 正式申请新建升版物料，填写旧新版本、公司库存和客户现场备注，统一保存并核对接口。
2. 设置公司库存成品为 NA，实际 PATCH 只包含该格；已有备注保留。
3. 刷新后重开恢复。清空公司库存备注时模拟一次 503，输入保留并可重试；实际 PATCH 只包含该备注，NA 和客户现场内容保留。
4. 新增类别仅填写基础物料，没有处置页签；保存成功。
5. 停用类别填写项目及供应商 RMA 备注，真实创建后模拟客户端响应丢失，再次保存返回同一 ID，处置未丢失且没有重复物料。
6. 退出并重新登录，三类物料及全部已填处置正确恢复，正式页面没有原型标签；停用筛选仅显示停用记录。

浏览器未记录未捕获运行错误。回归工具需要等待抽屉和下拉定位稳定；另一次刷新丢失脚本的临时申请 ID，重新从接口获取 ID 后继续验证，两者未作为业务缺陷修改。正式页面截图 `.local/formal-disposition-list.png`；结果摘要 `.local/stage4-disposition-results.json`。临时账号、申请、物料、处置、会话及凭据清理，用户数据和服务保留。
