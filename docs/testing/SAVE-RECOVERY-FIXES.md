# 三项保存与恢复问题修复

范围：仅前端物料同步、物料保存确认、共享 API 请求期限及必要回归。保留当前未提交改动；后端、数据库结构、迁移和业务规则未变。

## 已复现问题与修复

1. **处置删除被重新写回。** 审查中服务器删除 company_finished 后，干净抽屉重登仍显示旧 NA／备注，随后只改描述的 PATCH 包含旧处置。现在表单使用当前受保护草稿的完整显示快照，显式清空曾存在但当前已不存在的处置字段；PATCH 仍只包含差异。没有在每次输入时 resetFields，不主动重挂载控件。脏输入、在途新输入和未知结果继续由原队列保护。
2. **异常成功响应丢输入。** 原物料新增收到 `200 {}` 或数组会关闭抽屉、提示成功。现在先验证非数组对象、正整数 ID、类别、适用文字字段及合法处置结构；已有记录 ID 必须相同。失败抛出结果未确认错误，在更新缓存／基线之前停止，保留输入、抽屉和新增 UUID。校验仅用于物料保存，列表的正常数组响应仍兼容。
3. **无响应永久阻塞。** 原 fetch 无等待上限，手动保存一直等待同一 flight，输入、导航和重登都锁住。现在每次 API 调用有 30 秒总期限，CSRF 获取、主请求和正文读取共享同一 AbortSignal；期限竞争保证不响应取消的模拟传输也能结束调用。计时器在完成后清理；迟到响应在处理账号事件之前检查取消，不更新调用方。读超时显示读取失败，写超时显示结果未确认；客户端取消不代表服务器未写入。原 5／15 秒有限重试与首次新物料手动创建机制保留。

入口：`frontend/src/materialSave.ts`、`MaterialEditor.tsx`、`api.ts`。没有新依赖、全局表单框架或后端并发版本机制。

## 九组隔离模拟页面回归

独立 agent-browser 会话加载当前页面，所有 `/api/` 被模拟拦截，无真实身份或数据库写入。复用审查时的 `.local/review-init.js`；本批脚本／结果为忽略的 `.local/verify-save-repair.cjs`、`.local/save-repair-results.json`。

1. 干净重登刷新后，服务器删除格的处置与备注都清空；只改描述的 PATCH 仅含 description，模拟服务器不重建处置。
2. 脏处置重登保留本地备注，随后正常保存。
3. 在途保存后继续改描述，响应不清空后续输入；最终保存后续值。
4. 新增分别返回空对象、数组、缺字段、错误字段类型、非法 ID、错误类别、非法处置结构：抽屉不关闭、不提示成功、输入保持，同一 UUID。
5. 改为正常响应后，原未知结果输入成功确认，手动保存关闭。
6. 已有物料返回不同 ID：保持输入及未确认状态；正常重试才关闭。
7. 保存传输持续无响应，点击手动保存等待；约 30.390 秒后期限结束，随后受控一次 503，手动锁释放，输入／页签／重登可用。时间包括界面检查开销，不是精准耗时保证。
8. 释放已超时的旧 409 账号变化响应，不触发身份切换或覆盖输入。
9. 原有限重试随后正常保存恢复。
