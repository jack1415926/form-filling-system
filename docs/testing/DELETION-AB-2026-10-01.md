# 草稿删除与物料处置 AB 原型验证

日期：2026-10-01。该小批仅实现本人草稿删除及内存 AB 原型，不创建 `material_disposition`、不接正式处置保存，不开展其他工作表或审批留言。用户业务验收仍由人工复核决定。

## 接口与范围

`DELETE /api/changes/{id}/` 使用当前登录用户限定归属，事务内锁定申请并检查草稿状态。成功返回 204，非草稿返回 409，越权或不存在返回 404。现有 Django CASCADE 关系删除关联物料，申请删除后非空 ECR/ECO 编号可以复用。不新增软删除、回收站或数据库迁移。

列表确认框展示标题、ECR/ECO 编号及不可恢复提示；删除请求期间禁止其他删除、查看、新建、退出和重新登录。成功清理对应账号下的详情／物料缓存并刷新列表。失败提示错误并保留记录；404 提示“申请已不存在或不可访问，列表已刷新”，不宣称删除成功。

## 浏览器回归

使用已有 agent-browser 的独立 `form-draft-delete` 和 `form-ab-preview` 会话。

删除：独立临时账号及两条草稿，其中一条带物料。取消确认保留记录；模拟等待请求时新建／查看／删除／登录相关控件禁用；释放为 503 后显示错误且两条草稿保留；恢复实际 DELETE 后只删除目标，并核对关联物料消失。另一条在其他连接删除后，旧确认框的 DELETE 实际返回 404，列表刷新为空且提示准确。

AB：初始均为三条样例，处置没有默认 NA。A 保存处置后 B 打开恢复，B 单独保存后 A 也恢复；取消未保存关闭保留输入。A 的新建可在同一抽屉填写处置并保存；B 新建先保存基础物料。新增物料没有处置页签或按钮。重置恢复三个真实样例行，网络资源核对无 `/api/` 请求；页面内部没有正式 API 调用。对照截图 `.local/ab-layout-a.png`、`.local/ab-layout-b.png` 已进行视觉检查，抽屉宽度均为 720，底部按钮固定。

回归中遇到抽屉打开动画及 Ant Design 表格测量行影响工具定位／行数统计，等待定位稳定并按 `data-row-key` 统计真实行后验证通过；未据此改造应用或新增测试基础设施。

本机摘要 `.local/stage3-deletion-ab-results.json`。临时回归账号、申请、物料、会话和凭据已清理，用户人工复核数据及服务保留。原型无数据库数据。

## 人工对照与停止点

正式申请入口：`http://localhost:5173`，在“我的申请”对自己不需要的草稿核对删除确认；删除不可恢复。

原型入口：`http://localhost:5173/?preview=disposition`。对照 A 的“物料信息／处置建议”页签及统一保存，与 B 的“编辑物料／处置”两个入口及分别保存。可新增、修改、保存预览、重开、切换布局及重置样例；刷新会清除预览修改。

候选 Use-up、Scrap、Rework、No Change、Balance、NA 仅用于布局对照，未确定分类适用业务规则。此次不选择默认正式布局，不实现正式处置表和持久化；选定后再开下一小批。
