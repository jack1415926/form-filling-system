# 整项工程变更永久删除

日期：2026-10-16。

## 需求与实现

原来只允许删除本人ECR草稿，ECO来源受保护；用户确认先做整项永久删除。现在有效ECR发起人可从ECR列表删除任意状态的整项工程变更，包括待修订、审核中、待批准、已批准及已发布；有关联ECO时，确认窗口显示两份流程的编号、ID和状态，必须勾选“同时删除关联 ECO”，否则无法提交，取消保留两者。ECO不提供独立删除。

复用DELETE申请接口，保留CSRF、当前账号、所有者校验；非草稿要求显式确认，有ECO还要求明确勾选和匹配的关联ID。列表过期、确认后新建ECO或关联ID不符均返回409，不删除任何记录。在一个事务内锁定ECR与ECO，先删除ECO再删除ECR，复用现有级联关系清理表单、人员关联、任务／操作回执、审核／意见／轮次快照、批准／发布、填写交接及已读记录。失败全回滚，不改数据结构或迁移，不增加回收站。账号、独立系统反馈和其他工程保留。

列表删除能力由发起人身份决定，不再限草稿；其他审核／批准／发布／ECO填写身份和管理员身份不额外授予权限。删除成功清理两份流程的本地缓存并刷新列表、待办和提醒。新组件只负责确认和勾选，避免在列表回调中维护窗口状态。

## 验证

- 22项真实MySQL专项通过：新增5项删除测试，覆盖ECR各五种场景及待修订、关联ECO各五种场景、未勾选／范围过期拒绝、权限及严格输入、完整关联图清理、编号释放、独立反馈／账号／其他申请保留、中途失败回滚；同时复验工程列表、发布及既有删除的所有者／CSRF边界。独立测试库已销毁。
- 3项前端工程列表专项、TypeScript／Vite构建、lint通过。构建使用原生配置加载器，保留既有大包提示；未执行全量回归。
- 独立MySQL浏览器环境新建ECO待批准及其已发布来源ECR，确认发布态ECR可见删除入口，窗口正确列出ECR #3及ECO #4；未勾选按钮禁用、勾选后启用，取消后接口确认两份记录仍存在。随后用同一隔离环境的登录／CSRF链路调用DELETE返回204，两份详情均404，未关联的ECR #1仍可读取；重新登录页面后确认ECR列表只剩未删除申请、ECO列表为空。未在浏览器点击永久删除按钮；实际删除由隔离接口验证。

## 使用

刷新内网页面，以ECR发起人登录，进入“工程变更 → ECR流程 → 删除整项工程变更”。核对范围，有关联ECO时勾选“同时删除关联 ECO”，再点击“永久删除整项”。该操作删除真实记录且无法恢复，其他设备的真实操作验收仍需单独完成。当前业务规则见[MVP](../MVP.md)。
