# ECR / ECO 双流程 A/B 页面原型（2026-10-13）

当前主界面仍同时陈列ECR、ECO页签并显示连续六阶段进度，容易让两条独立记录看起来像一份申请。先按用户要求提供可点击的A/B原型，尚未选定或应用正式界面方案。

## 页面方案

A版从ECR流程、ECO流程分别进入列表；B版按来源ECR分组展示工程变更，分别打开两份流程。两版共用详情、八表填写组件及内存示例，不删除ECR或ECO Sheet。ECR内ECO仅展示待启用行动模板；ECO内ECR展示已发布来源逐人结果，只读。详情只显示本流程状态、轮次、任务及人员；整体关联在工程变更总览展示。

本机预览位于frontend/.local/workflow-ab-preview/，属于忽略目录。正式代码仅为现有OverviewEditor增加可复用导出，没有改后端、迁移、业务数据、批准规则或正式主界面。当前其他未提交改动继续保留。

## 隔离与能力

独立Vite配置仅监听127.0.0.1:5181，不配置后端代理；模拟层拦截所有/api请求，未知路径明确拒绝，不转发。固定定义来自现有项目，申请和账号均为示例。模拟保存、创建ECO及本人任务填写只写浏览器内存，刷新或重置恢复初值；状态选择展示预设场景，不另写完整审批引擎。

创建仅从已发布ECR执行，一对一且重复创建不覆盖；独立复制全部基础表，ECO编号留空，负责人、批准人、发布人、任务及历史不继承。原ECR保持发布只读。正式意见与审核历史仅用样例展示，不代表真实多账号业务验收。

## 验证结果及边界

- 原型5项专项通过：基础表复制及来源不变、重复创建不覆盖；真实前端响应校验与任务权限／实施状态；指定填写人与只读跟踪；未知接口及绝对API URL不转发；长期身份保留及重置。使用node --test --test-isolation=none，避免当前沙箱的测试子进程EPERM。
- 包含现有生产组件及原型的TypeScript检查通过；未执行后端测试、数据库迁移或全量产品测试。
- 实际浏览器打开八表及历史入口，无读取或响应校验错误；ECO概述内存保存后来源ECR标题和已发布状态不变。
- 切页出现保存／放弃／继续填写保护；保存并切换成功，A/B切换保留当前ECO与保存内容。
- B版显式启动独立ECO成功；来源多人结果在主表及抽屉完整只读。本人ECO任务保存结果成功，“在实施阶段完成”仍禁确认。
- 700像素窗口下的详情布局无页面横向溢出，临时窗口设置已恢复。页面截图位于同一忽略目录的preview-a.jpg、preview-b.jpg及preview-detail.jpg。

正式ECR/ECO产品改造、最终页面选择、完整业务验收及部署尚未执行。5181仅用于本原型，不能作为正式网页服务或公司内网访问证据。

## 原型修复

2026-10-14：正式`npm run lint`曾扫描本机`.local/workflow-ab-preview/main.tsx`，因组件未导出和未使用的`revision`报错。ESLint此前只排除`dist`；现将`.local/**`加入全局忽略，保留预览文件。正式`npm run lint`已通过；本次仅验证lint，未重跑构建、业务测试或数据库迁移。

最后检查发现长时间停留后关闭任务抽屉出现空白：原型手动初始化的身份缓存没有查询观察者，默认5分钟后回收，现有组件读取身份时失败。仅在预览QueryClient中将身份缓存保留到重置或刷新，补充浏览器环境下推进10分钟模拟时钟的检查；正式身份接口和组件未改。
