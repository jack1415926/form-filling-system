# ECR／ECO 测试数据

从项目根目录运行，使用现有账号，不需要 Django 管理员或 Windows 管理员权限。数据库应已启动并迁移至当前版本，`.local/development.json` 中 `DJANGO_DEBUG` 为 `1`。

## 网页操作（推荐）

登录系统，进入**工程变更 → 生成测试用例**。默认选择 **ECR → 待批准 → 全部由我测试**，点击生成后可直接打开新申请。需要多账号测试时，选择“分别指定人员”：行动负责人、批准人均可多选，至少各选一人；发布人选择一人，申请人固定为当前登录账号。所选负责人共同负责问题6对应的11项行动，提交后每项行动为每人各生成一份任务；所有负责人确认后，全部批准人同意才会批准。审核中保留全部任务待确认，待批准保留全部批准人待批准，已批准／已发布自动完成全部人员对应步骤。

支持 ECR／ECO 和下方五种状态；每次生成一个目标场景，ECO 同时创建新的已发布来源 ECR。生成成功显示编号和申请 ID，点击“再生成一个”可继续操作。同一次生成请求在网络中断后以相同选择重试，会返回原用例，避免重复生成。已有用例经人工修改后若不能恢复原回执，提示核对原申请，不覆盖修改。

入口仅在 `DJANGO_DEBUG=1` 的开发测试环境显示；非开发环境服务端返回404。普通有效账号即可使用，不需要管理员权限。更新后若按钮未出现，刷新网页或点击“刷新身份”；新增后端代码需要重启后端。

## 交互选择

```powershell
pwsh -NoProfile -File scripts/test-data.ps1
```

依次选择 ECR／ECO／两种流程、目标状态／全部，输入申请人的**登录名**。其他三种人员默认与申请人相同，便于一个账号完成测试；脚本不会创建账号或修改密码。

## 指定场景和人员

```powershell
# 示例登录名须替换为本机已有有效账号
pwsh -NoProfile -File scripts/test-data.ps1 -Stage eco -State pending_approval -Applicant user1 -Reviewer review1 -Approver review2 -Publisher user2

# 一次生成 ECR、ECO 各五种场景
pwsh -NoProfile -File scripts/test-data.ps1 -Stage all -State all -Applicant user1
```

| State 参数 | 场景 | 实际进度 |
| --- | --- | --- |
| draft | 草稿 | 正文填好、人员指定，尚未提交 |
| reviewing | 审核中 | 已提交，行动结果已填好，但负责人尚未确认 |
| pending_approval | 待批准 | 行动全部确认，指定批准人尚未批准 |
| approved | 已批准 | 指定批准人已批准，指定发布人尚未发布 |
| published | 已发布 | 发布完成，正文只读 |
| all | 全部 | 分别生成以上五种场景 |

审核中、待批准在现有数据库中均为 `pending`；现有列表统一显示“审核中”，具体进度从行动确认数及批准待办查看。脚本不新增业务状态，待修订 `returned` 不在本次五种测试场景中。

申请标题、编号以 `[测试]`、`TEST-` 标识，输出申请 ID、编号和各人员登录名。按账号登录后，在工程变更列表找到对应记录，继续执行提交、任务确认、批准或发布。默认样例为自制、非关键、非可追溯、非维修备件的连接件物料A→B升版，仅规范内部受控描述；实物、规格、用途及工艺不变，不涉及外购件或供应商。问题6为“是”，其余26题为“否”并说明场景假设，物料按升版录入、十处处置为No Change。

ECR／ECO各自只生成定义中问题6对应的11项行动；不填充问题1等未触发行动，不勾选额外必做。ECR评估逐项给出与场景匹配的结果；ECO中无需新增措施的行动填写不适用原因，保留互换性核对。两类状态均沿正常任务／批准规则推进。问题7为“否”，EMC保留参考模板而不填测试或备注；执行计划仅填“物料的验证与发布”，实质性评估按合成假设走0否→A否→B否，未经过的Chart和子题留空。该人工评估只用于合成测试场景，不代表真实产品判断。

ECR不启用ECO Sheet；ECO的ECR Sheet始终只读引用来源已发布结果，ECO自身行动按本单答案生成。若本单27题全否且没有手工补充行动，则本单不应生成行动人员、结果或任务；这不清空ECO的来源ECR历史。2026-10-16修复前生成的旧样例及其冻结快照不自动回写，请重新生成用例测试。

每个 ECO 场景会先新建并完整发布一份来源 ECR，再通过正式复制接口创建 ECO。一次生成全部场景会新增 **15条申请：10条目标申请＋5条来源 ECR**。每次运行都新增，不覆盖、回退或删除已有申请。正文使用合成样例，不复制真实业务数据；来源创建、提交、任务确认、批准、发布走当前业务接口并保存快照及回执。任一步骤失败，本批新增数据全部回滚。

也可直接运行后端命令，参数相同：

```powershell
pwsh -NoProfile -File scripts/backend.ps1 seed_workflow --stage ecr --state reviewing --applicant user1
```
