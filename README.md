# 表单填报系统

面向电脑端的设计变更填报系统，将指定八张Excel工作表转换为网页。技术栈为React、TypeScript、Vite、Ant Design、TanStack Query、Django REST Framework和MySQL。

## 新ECR当前规则

- 发起人在draft／returned填写基础内容、选择行动负责人、补充行动及发布人。行动结果由负责人在提交后填写，不能由发起人在草稿代填。
- 提交要求标题和ECR编号非空、27题全部回答、纳入行动负责人及发布人有效。回答“是”的行动自动纳入，也可手工补充；零任务须明确确认并留下记录。
- 提交后pending显示为处理中，基础内容、人员和任务范围锁定。本人可以承担自己的任务，仅按该任务权限处理。
- 负责人保存结果说明、业务状态及日期，三项完整后明确确认；不适用也需原因。确认后该任务只读，不由自动保存代替确认。
- 任一负责人退回会结束整个当前轮次。重提创建新任务，旧结果仅为待复核初值，旧确认不计入新轮；未解决意见必须回应并由原提出者复核。
- 所有本轮任务确认且阻断意见解决后进入approved。本批终点是ECR阶段已批准，仍不代表已发布。
- 任务快照按轮保留，基础表不保存完整逐轮版本。legacy的整单批准入口拒绝新ECR。

旧申请仍按原指定人员全部批准处理，新增公开审核已停用；历史公开记录保留原访问范围及两人批准规则。旧流程禁止发起人整单自审，不影响新ECR允许本人承担任务。

## 数据保护与恢复

局部PATCH、CSRF、X-Expected-User、申请行锁、事务及请求UUID继续保留。基础字段仅本人草稿／退回可写；处理中只有指定负责人可写自己的当前未确认任务，其他字段只读。

任务保存先确认冻结请求，再保存后续修改，避免旧回执覆盖新输入；阶段GET按updated_at保留较新缓存。工作台合并意见与任务编辑状态，未保存时提示，在途／结果未知时阻止离开，但保留查询／重试入口。确认优先检查原UUID；任务终态、旧轮或版本变化会释放不可重试操作的保护。

自动保存停顿2秒触发，新物料首次创建手动确认。失败保留输入，原账号重新登录可恢复；已读不完成业务待办。没有异常退出后的本地备份保证，也没有基础表通用多人编辑版本冲突控制；行动任务另有version校验。
