# 表单填报系统

面向公司内网电脑端的设计变更填报系统，将指定的八张 Excel 工作表转为网页填报。技术栈：React、TypeScript、Vite、Ant Design、TanStack Query、Django REST Framework、MySQL 8.4。

## 使用与当前规则

- 打开[本机网站](http://localhost:5173/)，登录后新建或打开本人申请，按页签填写。八张源工作表在网页合并为八个填写页签，另有第九页“提交审核”。
- 八页实际修改停顿2秒自动保存，保存期间可继续输入。网络／5xx／未确认结果在5秒、15秒各重试一次，再失败等待手动重试；身份和权限错误暂停。保留手动保存及保存并切换；新物料首次创建须手动确认。放弃修改只丢弃尚未保存部分，没有异常退出后的本地恢复保证。
- ECR／ECO默认仅显示已保存问题回答为“是”的行动；隐藏不删除旧填写，“全部行动”仍可查看。两页独立联动，ECO不依赖ECR完成状态。`?preview=ecr`仍是内存演示，正式填报使用无查询参数入口。
- 日期年份为2000～2100；不完整、不存在或超范围日期阻止所在表单保存。执行计划开始／结束均填写时，结束不能早于开始。
- 提交要求标题与ECR编号非空。指定审核至少选一名有效审核员，所选人员全部批准后通过；公开审核需两名不同审核员批准。按钮“本人同意批准”记录个人决定，满足条件才整单通过。
- 退回后本人可修订；须逐条回应未解决意见后重提，存在未解决意见时沿用原审核安排。重提开启新轮、重新计算批准，原提出者复核自己的意见；未解决意见阻止整单批准。旧普通留言停止新增并只读保留。
- 系统反馈独立于申请审核。用户只看本人，提交后正文只读、可追加追问或意见、无附件；反馈管理员使用附加组权限，superuser／staff不会自动获得业务角色。
- “标为已读”只清除审核提醒，消息和业务待办保留；新入站事件或轮次再提醒。普通表单修改及本人处理不重复制造未读。
