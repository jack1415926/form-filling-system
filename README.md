# 表单填报系统

面向公司内网电脑端的设计变更填报系统，将八张 Excel 工作表逐步转为网页填报，并支持多人并行审批及留言。技术栈：React、TypeScript、Vite、Ant Design、TanStack Query、Django REST Framework、MySQL 8.4。

## 当前进度

更新日期：2026-10-01。**概述草稿及本批三类物料明细已实现并完成技术验证；阶段一用户业务复验按用户要求暂缓，仍未验收。用户已授权继续本批，不等待人工复验。**

[PR #1：落实草稿 ECR/ECO 编号唯一规则](https://github.com/jack1415926/form-filling-system/pull/1) 为此前编号规则交付，功能提交 `81d3f2f`，目标分支 `main`；此前记录为 OPEN，本批未查询远端状态。物料、处置、草稿删除及审查修复在 `codex/enforce-unique-change-numbers` 分支交付。

已实现：

- 登录、退出和单账号单有效会话；同浏览器多个窗口共享 Cookie，属于同一会话。
- 我的申请、新建概述草稿、11 个业务字段填写、保存及重新打开恢复；仅提交修改字段，失败保留输入，离开时提醒未保存内容。
- 概述底部“保存草稿”旁的“下一页”跳转至物料明细；不自动保存，未保存时沿用确认提示，成功跳转后回到页首。
- 用户数据隔离、系统字段只读、非草稿禁止修改，以及保存事务和行锁。
- 非空 ECR/ECO 编号分别全局唯一，空编号允许重复；接口校验及数据库约束覆盖并发写入，迁移前发现重复则停止并报告申请 ID。
- 申请详情的概述／物料明细页签；升版、新增、停用三类物料的分组列表、单条抽屉编辑、确认删除、保存和重新打开恢复。
- 物料号及版本按文本保存，保留前导零；Y/N 支持未填写；三类差异字段校验、类别保存后不可转换，写入同步申请更新时间。
- 物料接口沿用用户隔离、CSRF、草稿限制和申请行锁；抽屉失败保留输入，编辑仅提交修改字段，删除正确处理 204 响应。
- 我的申请支持确认后永久删除本人草稿，并级联删除已保存物料、释放 ECR/ECO 编号；非草稿、越权和缺少 CSRF 的删除由后端拒绝。
- 物料处置已接入正式申请：升版／停用的物料抽屉内提供物料信息和处置建议页签，一起保存；新增物料不提供处置。列表支持类别筛选（含不限），处置重开／重登恢复，删除物料或草稿时级联清理。

未实现：其他工作表、提交审批、审批任务、留言和导出。当前已完成第一张表的概述、三类物料及十个位置处置填写保存；完整业务规则仍需人工复核。

本批技术验证：38 项真实 MySQL 后端测试、Django 检查、迁移一致性、前端 lint/build 通过；8 组本机浏览器回归通过。本机已应用 `0003_materialchange`，迁移前后的原申请数据一致，没有预填物料。详情见 [物料验证记录](docs/testing/MATERIALS-2026-10-01.md)；此前概述证据见 [阶段一复查记录](docs/testing/REVIEW-2026-09-30.md)。均不代表用户业务验收或正式部署通过。
