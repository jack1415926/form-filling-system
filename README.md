# 表单填报系统

面向公司内网电脑端的设计变更填报系统，目标是将现有八张 Excel 工作表转换为网页填报，并支持保存恢复、并行审批和留言。技术选型为 React、TypeScript、Vite、Ant Design、TanStack Query、Django REST Framework 和 MySQL 8.4。

本文是**当前进度、待办和下一步的唯一汇总入口**。需求与总体计划见 [MVP](docs/MVP.md)，启动方法见 [开发说明](docs/DEVELOPMENT.md)，测试证据见 [复查记录](docs/testing/REVIEW-2026-09-30.md)。

## 当前进度

更新日期：2026-10-01。此前功能基线：`e5f25ed`；本轮改动包括编号功能、迁移、必要测试和文档。**编号唯一规则已完成，仍待用户业务复验，阶段一尚未验收关闭。** 本批只精简并交付现有功能，没有进入物料、其他工作表或审批留言开发。

- 已实现登录、我的申请、新建概述草稿、保存及重新打开恢复，使用真实 MySQL。
- 已实现申请者权限、系统字段只读、非草稿保存拒绝、保存事务和行锁。
- 已修复整表提交覆盖未修改字段的问题，改为仅提交编辑过的字段；保存失败保留输入，清空日期正确保存。
- 已修复共享 Cookie 的窗口重新登录后持续 CSRF 失败的问题，错误提示放在保存按钮附近。
- 已实现新登录使旧登录会话失效，覆盖应用和 Django 管理后台；同浏览器共享 Cookie 的窗口属于一个会话。
- 已实现非空 ECR/ECO 编号分别全局唯一：接口校验、数据库生成列唯一约束和并发冲突字段提示；多个空编号允许保存，编辑原编号及清空后复用合法。
- 已实现迁移前重复检查；存在重复时在 DDL 前停止并列出申请 ID，不自动修改业务数据。
- 新机器 MySQL 已对齐到 8.4.11；备份及旧数据核对证据保留在 `.local`。共享代码默认后端 8000；本机通过不提交的配置使用 8001，前端保持 5173。
- 已恢复原始 Excel 并只读核对 11 个概述字段，源文件哈希保持不变；旧机人工反馈原件及截图目前尚未恢复，已有问题按旧复查记录摘要回归，仍待用户复验。

已验证：真实 MySQL 8.4 上 28 项后端测试（含原 19 项）、Django 检查、迁移一致性及前端 lint/build 通过，包含并发同号保存、直接写库拒绝重复、旧数据迁移及回退。此前 9 组浏览器回归证据保留在 `.local`；本批移除自制浏览器/Excel 工具，不再维护该工具套件。正式部署和用户业务验收不计为通过。
